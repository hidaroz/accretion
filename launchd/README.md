# Autonomous weekly memory curation (launchd)

Runs `/memory-weekly --autonomous --vault <id>` every week, unattended, via a
macOS launchd agent. It synthesizes digests, **proposes** brief updates, archives
digest-covered sessions, commits, writes a run report, and fires a notification.

The run never edits brief content. Brief edits are semantic judgments, so
confidence-gated unattended auto-apply was removed (docs ADR-007, see
`docs/DESIGN.md` → "Review outcome"). Proposals land in
`proposals/brief-updates/` and a human applies them with
`scripts/memory-apply-proposals.mjs --apply`. Deterministic housekeeping —
digests, `last_reviewed` stamps, archiving — stays automatic.

Pushing is gated on the vault's `gitAutoPush` in
`~/.config/obsidian-mcp/vaults.json`. For `work` it is `false`, so the run commits
locally and does not push.

## Files
- `~/.claude/commands/memory-weekly.md` — the command itself. **Not installed by
  `bootstrap.mjs`;** if it is missing, both the scheduled and the manual path fail.
- `bin/memory-weekly-run.sh` — the wrapper launchd executes (headless `claude -p`).
- `infra/launchd/com.memory-weekly.<vault>.plist` — the schedule (Mon 09:00).
  Generated by `setup-vault.mjs --launchd`; it is not checked in.

## One-time setup

1. **Generate the plist** — it does not exist until you ask for it:
   ```bash
   node scripts/setup-vault.mjs --id work --path ~/Documents/work-vault --launchd
   ```

2. **Supervised first run** — validate permissions and auth before trusting the
   schedule:
   ```bash
   bin/memory-weekly-run.sh work
   tail -f ~/Library/Logs/memory-weekly/work/$(date +%Y-%m-%d).log
   ```
   Confirm it produced digests and proposals, wrote
   `sessions/digests/_runs/{today}-memory-run.md`, committed, and notified. If a
   permission prompt blocked it, widen `--allowedTools` in the wrapper.

3. **Install + load the agent:**
   ```bash
   cp infra/launchd/com.memory-weekly.work.plist ~/Library/LaunchAgents/
   launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.memory-weekly.work.plist
   ```

4. **Trigger a scheduled-path run on demand** (verifies launchd wiring — this is
   the step that catches a plist that was generated but never loaded):
   ```bash
   launchctl kickstart -k gui/$(id -u)/com.memory-weekly.work
   ```

## Manage
- Status: `launchctl print gui/$(id -u)/com.memory-weekly.work`
- Logs: `~/Library/Logs/memory-weekly/work/` (per-day `claude` log + launchd out/err)
- Unload: `launchctl bootout gui/$(id -u)/com.memory-weekly.work`

## Notes
- launchd runs a missed weekly job on the next wake, so a sleeping Mac just
  delays the run rather than skipping it.
- The job needs you logged in (a GUI launch agent) and the `claude` CLI
  authenticated. It runs entirely locally — nothing leaves the machine.
- **The failure mode to watch for is silence.** This pipeline has died quietly
  twice: once when the capture hook vanished (2026-07-28), once when the agent
  was generated but never loaded (2026-08-05, unnoticed for six weeks). Nothing
  broke loudly either time. `scripts/doctor.mjs` now checks that the agent is
  loaded, that a run report exists from the last 10 days, that no digests are
  backlogged, and that the embedding index is not stale — run it if the vault
  ever feels out of date.
